## 3. A. Google Trends

**입력**: trends.google.com
**출력**
- `data/raw/google_trends/<keyword>_<받은날짜>.csv` (원본 그대로)
- `data/processed/weekly_trends/weekly_trends.csv`
- `data/processed/weekly_trends/spikes.csv`

**할 일**
1. 조회 조건을 고정한다: 지역 미국, 기간 2018-01-01 ~ 2022-12-31, 카테고리 전체, 웹 검색. 5년 이하 기간이라 주 단위로 나온다.
2. 기준 키워드 `blanket`을 모든 묶음에 넣는다. 한 번에 최대 5개라서 `blanket` + 키워드 4개씩 받는다.
3. 같은 조건으로 서로 다른 날 3번 받는다. 받은 날짜를 파일 이름에 넣는다.
4. `<1`은 0.5로 바꾼다.
5. 3번 받은 값을 평균낸다.
6. 기준 키워드로 환산한다: `값 × (첫 묶음의 blanket 값 / 이 묶음의 blanket 값)`. 주마다 계산한다.
7. 키워드를 `mapping/keyword_product_mapping.csv`로 product_type에 붙인다. 한 품목에 키워드가 여러 개면 평균낸다.
8. spike 표시: 직전 12주(이번 주 제외)의 평균과 표준편차로 z를 구하고, z ≥ 2이면 spike다. 앞 spike와 8주 안에 붙어 있으면 하나로 본다.
9. 계절성 보정본도 만든다: 전년 같은 주 대비 차이(`trends_yoy`). 2018년은 전년이 없어서 비워 둔다.

**결측·이상치**
- 빈 주가 있으면 0이 아니라 결측으로 두고 로그에 적는다 (Trends는 보통 빈 주가 없다).
- 3번 받은 값이 크게 다른 주(최대−최소 > 20)는 로그에 적는다.

**출력 컬럼**: `week, keyword, product_type, trends, trends_yoy, is_spike`
**선택**: 같은 방법으로 "Google 쇼핑" 검색도 받아 두면 비교용으로 좋다.

## 4. B. 구매 데이터

**입력**: `data/raw/open_ecommerce/amazon-purchases.csv` (1,850,717행, 응답자 5,027명)
**출력**
- `data/interim/cleaned_purchase/purchases_clean.csv` (또는 .parquet)
- `data/processed/weekly_purchase/weekly_purchase.csv`
- `data/interim/cleaned_purchase/asin_list.csv` (C에게 전달)

**할 일과 결측치 처리** (숫자는 2018~2022 원본 기준)

| 단계 | 처리 | 원본 규모 |
| --- | --- | --- |
| 컬럼명 통일 | `order_date, unit_price, quantity, state, title, asin, product_type, response_id` | |
| 기간 | 2018-01-01 ~ 2022-12-31만 남김 | 1,810,793행 |
| ASIN 결측 | 행 삭제 (조인 불가) | 963행 |
| Category 결측 | 행 삭제. 품목을 알 수 없고 Title도 같이 비어 있음 | 89,235행 (4.9%) |
| 완전 중복 행 | 삭제. 모든 컬럼이 같은 행은 중복 추출로 판단 | 11,361행 |
| ASIN 표기 | 앞뒤 공백 제거, 대문자로 통일 | |
| 가격·수량 | 결측·0은 없음. 단가 > $1,000(472행)과 수량 > 10(567행)은 삭제하지 않고 `is_outlier` 표시만 | |
| 주소 주(State) 결측 | 그대로 둠. 분석에 안 씀 | 87,812행 |
| 품목 필터 | 1장의 6개(+예비 2개) product_type만 남김 | |

**주간 집계**
- `week` = 주문일이 속한 주의 일요일 날짜.
- `purchase_count` = 주문 행 수 (메인 지표), `quantity_sum` = 수량 합 (보조).
- 구매가 없는 주는 **0으로 채운다**. 품목 × 261주 전체가 있어야 한다.
- **표본 보정**: 그 주의 활동 응답자 수로 나눈 `purchase_rate` = purchase_count / 활동 응답자 × 1,000. 활동 응답자 = 첫 구매일 ≤ 그 주 ≤ 마지막 구매일인 응답자. 연도별로 구매 기록이 있는 사람 수가 달라서(2018년 4,281명 → 2022년 4,868명) 필요하다.

**출력 컬럼**: `week, product_type, purchase_count, quantity_sum, purchase_rate`
**asin_list.csv 컬럼**: `asin, product_type, purchase_rows`
**보고**: 품목별 행 수와 단계별로 지운 행 수를 로그에 표로 남긴다 (발표 슬라이드용).

## 5. C. 리뷰 + 통합 (김지우)

**입력**
- 리뷰 원본 3개: `data/raw/amazon_reviews/{Home_and_Kitchen, Health_and_Household, Toys_and_Games}.jsonl.gz` (8.3GB, 3.2GB, 1.9GB)
- B의 `asin_list.csv`

**출력**
- `data/interim/filtered_reviews/reviews_filtered.parquet`
- `data/processed/weekly_reviews/weekly_reviews.csv`
- `data/processed/integrated/integrated_weekly.csv`

**할 일**
1. 리뷰 파일은 압축을 풀지 말고 한 줄씩 읽는다 (DuckDB `read_json` 또는 chunk 읽기). 메모리에 통째로 올리지 않는다.
2. `asin`이 `asin_list.csv`에 있는 리뷰만 남긴다. 구매 데이터에 없는 ASIN의 리뷰는 버린다.
3. `timestamp`는 밀리초 UTC다. 날짜로 바꾸고 2018~2022만 남긴다.
4. 남길 컬럼: `asin, parent_asin, product_type, rating, title, text, review_date, helpful_vote, verified_purchase, user_id`.

**결측·중복 처리**

| 대상 | 처리 |
| --- | --- |
| `rating` 또는 `timestamp` 결측 | 행 삭제 |
| `text`가 빈 리뷰 | 남김. 리뷰 수·평점에는 쓰고 감성 분석에서만 뺌 (Home_and_Kitchen 표본 30만 건 중 12건) |
| `images` | 쓰지 않음 (대부분 비어 있음) |
| 중복 리뷰 | `user_id + asin + timestamp + text`가 같으면 하나만 남김 |
| `verified_purchase = False` | 남기되 컬럼 유지. 인증 구매만으로 다시 계산해 보는 비교용 |

**주간 집계**: `week, product_type, review_count, avg_rating, share_1star, share_5star, verified_share` (감성은 10/2 이후 추가: 제목+본문에 VADER, `sentiment`)
- 리뷰가 없는 주: `review_count`는 0, `avg_rating`은 결측으로 둔다 (0으로 채우지 않는다).
- `share_1star`, `share_5star`는 J자 분포를 확인하기 위해 넣는다.

**통합** (10/6~10/8)
- 기준 표 = 품목 × 261주 전체.
- 여기에 A의 `weekly_trends`, B의 `weekly_purchase`, 위의 `weekly_reviews`를 `week + product_type`으로 **left join**한다.
- 최종 컬럼: `week, product_type, trends, trends_yoy, is_spike, purchase_count, purchase_rate, review_count, avg_rating, sentiment`

**보고**: 품목별 리뷰 매칭률(ASIN 기준, 구매 행 기준)을 표로 남긴다 (발표 슬라이드용).

## 6. 계절성·해석 주의 (A·B·C 공통)

- 품목 대부분이 12월(연말)과 7월 중순(Prime Day), 11월 말(블랙프라이데이)에 튄다. 원본 주간 최고치가 2022-07-17, 2022-11-27에 몰려 있다.
